# UK Electricity Grid

Учебный проект по случайным процессам и стохастическим дифференциальным уравнениям на примере электросистемы Великобритании. Первая цель — смоделировать, как изменчивость спроса, выработки и доступности станций влияет на риск дефицита мощности в Англии, Шотландии и Уэльсе (GB).

**[HTML-карта сети](grid_prototype/exports/map.html)** · **[Схема интерконнекторов](grid_prototype/exports/endpoint_schematic.html)**

Откройте карту двойным щелчком из локального клона или скачайте HTML на GitHub через **Download raw file**. Для Leaflet и фоновых тайлов нужен интернет. Схема интерконнекторов открывается офлайн.

## Быстрый старт

Из корня клона в PowerShell, с Python 3.11 или новее:

```powershell
git switch Def
cd grid_prototype
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe acquire.py --without-repd
.venv\Scripts\python.exe build_grid.py
.venv\Scripts\python.exe -m unittest -v test_grid.py
Start-Process exports\map.html
```

После загрузки исходников сборка выполняется офлайн. Она создаёт CSV и журнал сопоставлений в `data/normalized/`, карту, схему и графы JSON/GraphML в `exports/`. Опубликованная карта построена без REPD. Чтобы воспроизвести расширенный вариант с REPD, запустите `acquire.py` без флага и повторите сборку. Скачивание сверяет SHA‑256 с [манифестом](grid_prototype/data/raw/manifest.json).

На карте 788 линий Cardiff, 275 сопоставленных трансформаторов и 13 реестровых привязок станций. С REPD привязок 17. В выбранной географии семь действующих на дату среза интерконнекторов, строящийся NeuConnect вынесен за пределы активного графа. В графе 61 компонента и 56 терминалов без строк метаданных. У 51 линии исходная длина равна нулю, у 83 трансформаторов не удалось однозначно определить концы. Реестровые привязки дают гипотезы подключения, а для расчёта режима нужны проверенные инъекции, параметры и лимиты. Подробности и атрибуция приведены в [описании прототипа](grid_prototype/README.md).

## План симуляций

1. **Почасовая база GB.** Свести спрос, генерацию и обмен с соседними системами на шкале UTC. Учесть переходы времени, знак импорта и встроенную генерацию, чтобы избежать двойного учёта. Сверить итоги с NESO и DUKES.
2. **Случайные отказы и ремонты.** Задать двухсостоянийную марковскую модель по группам технологий. Отдельно учитывать плановый ремонт и оценивать параметры на исторических данных.
3. **Последовательное Монте‑Карло.** Симулировать независимые годы и оценить LOLE (ожидаемые часы дефицита за год) и EENS (ожидаемая недоотпущенная энергия в МВт·ч) с доверительными интервалами. Для оценки по всей GB потребуется покрытие генерации и её доступности на уровне GB.
4. **Стохастический остаточный спрос.** Оценить сезонный профиль и калибровать процесс Орнштейна–Уленбека для остатка или ошибки прогноза. На отложенной зиме проверить автокорреляцию, хвосты и случаи высокого спроса при слабом ветре. Сравнить с простой эмпирической моделью и проверить чувствительность метрик.
5. **Перетоки и перегрузки.** Сверить топологию, напряжения, R/X, номиналы и распределение нагрузки с ETYS. После сверки построить базовый расчёт DC и проверить его на эталонных примерах. Затем изучить сценарные перегрузки.

Для следующих этапов нужны [почасовые входы, данные доступности и сетевые приложения](grid_prototype/README.md#simulation-inputs).
